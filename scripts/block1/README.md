## Choose your route

You only need **one** route. Both produce the same figure and both are supported for the whole course.

| | Route A · R in Positron | Route B · Python in VS Code |
|---|---|---|
| Good if | you are new to coding, or used R before | you used Python before, or want one editor for everything |
| Language | R | Python (R also possible) |
| Editor | Positron | Visual Studio Code |
| Run today's script | *File → Open Folder…* `lecture01_starter` → open `scripts/01_first_figure.R` → **Run** | open this folder in VS Code → terminal → `python scripts/01_first_figure.py` |

> R and Python are **languages**. Positron and VS Code are **editors**. The editor is where you write; the language is what runs.

### Route A — install R and Positron

1. Install **R** from <https://cran.r-project.org> (Windows: "base"; macOS: pick the Apple-silicon *arm64* build for M1–M4 Macs, *x86_64* for older Intel Macs).
2. Install **Positron** from <https://positron.posit.co> (free; Windows, macOS, Linux). Install R first: Positron finds it automatically.
3. Open Positron, choose *File → Open Folder…* and select `lecture01_starter`.
4. In the **Console**, run once:
   ```r
   install.packages(c("readr", "ggplot2"))
   ```
5. Open `scripts/00_setup_check.R` and press the **Run** button (top right of the editor). Every line should say `OK`.

*Already use RStudio?* That works too: open `lecture01_starter.Rproj` and click **Source**.

### Route B — install VS Code and Python

1. Install **VS Code** from <https://code.visualstudio.com>.
2. Install **Python 3.11 or newer**:
   - Windows: from <https://www.python.org/downloads/> — tick **"Add python.exe to PATH"** in the installer.
   - macOS: from python.org (or `brew install python` if you use Homebrew).
   - Linux: usually already installed; check with `python3 --version`.
3. In VS Code, install the **Python** extension (Extensions icon in the left bar → search "Python", publisher Microsoft).
4. *File → Open Folder…* → choose `lecture01_starter`.
5. Open a terminal (*Terminal → New Terminal*) and create a virtual environment:
   ```bash
   # macOS / Linux
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt

   # Windows (PowerShell)
   py -m venv .venv
   .venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   ```
   If PowerShell refuses to activate, run once: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.
6. Press `Ctrl/Cmd + Shift + P` → **Python: Select Interpreter** → choose the one in `.venv`.
7. Run `python scripts/00_setup_check.py`. Every line should say `OK`.

*Prefer R inside VS Code?* Install R (Route A step 1), then the **R** extension (REditorSupport) in VS Code, run `install.packages("languageserver")` in R, and use `Rscript scripts/01_first_figure.R` from the terminal.

## Project structure

```
lecture01_starter/
├── README.md                ← you are here: what this is and how to rerun it
├── lecture01_starter.Rproj  ← only needed if you use RStudio
├── requirements.txt         ← Python packages
├── .gitignore               ← files Git should ignore (we use this in block 2)
├── data/
│   ├── README.md            ← data dictionary for the practice file
│   ├── raw/                 ← original files; never edit by hand
│   └── processed/           ← anything your code produces from raw data
├── scripts/
│   ├── 00_setup_check.R / .py
│   └── 01_first_figure.R / .py
├── exercises/               ← coding refresher
└── outputs/
    └── figures/             ← figures are made by code, never saved by clicking
```

Three rules we keep for the whole course:

- **Raw stays raw.** Code reads from `data/raw/` and writes somewhere else.
- **Relative paths only.** `data/raw/file.csv`, never `C:/Users/anna/Desktop/file.csv`.
- **The script is the record.** If a figure cannot be regenerated by running a script, it does not exist yet.

## Reproduce the figure

From the project folder:

```bash
Rscript scripts/01_first_figure.R      # Route A / R
python  scripts/01_first_figure.py     # Route B / Python
```

Each script also writes your software versions to `outputs/` — part of making the result reproducible.
